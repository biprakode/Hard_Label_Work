# Ablation — session resume notes

_Last updated: 2026-06-27._

## What this task is

Additive ablation of the **Phase-3 reconstruction pipeline** on the 6 make_blobs
victims (no CIFAR). Spec: `ablation_tiny.md`. The pipeline method code is treated
as **read-only** — we measure the existing staged pipeline, we do not change it.

Five **cumulative** stages, each evaluated on held-out **X_test3**:
`0 RAW → 1 +BIAS → 2 +LR FIT → 3 +SIGN SEARCH → 4 +FROZEN REFINE (full)`, plus a
single non-staged **distillation** contrast row per victim. Metrics: Agreement,
Ext acc, Sign acc, EQS (structural 22/26/17/20).

## Files in this folder (lives inside the repo: Hard_Label_Work/ablation_tiny/)

| File | Role |

## Design decisions (confirmed with user)

- **Custom read-only harness** chosen because the CLI cannot isolate stages 0-2
  (`--from-scratch` bundles bias+fc5+sign). The harness composes the *same*
  pipeline functions in the *same* order/args as `run_one_model_enhanced.sh`.
- **Regenerate Phase-1/2 fresh per victim**, accept Phase-1 stochasticity, and
  **flag** any stage-4 cell that differs from the published headline by > rounding
  (the sanity-check section does this; tolerance 2 pp).
- Lives **inside the repo** so a reviewer can fire it with one script; README has
  an "Additive Phase-3 ablation" section.

## Arch-name mapping (important)

The "tiny" victim is the 64×64 make_blobs model. In the driver its arch flag is
`tiny`; inside the pipeline the arch_key is **`makeblobs`** (model file
`tiny_stuff/makeblobs_{relu,leakyrelu}.pth`). `run_ablation.sh` maps
`tiny → makeblobs` for the harness automatically.

## Small-box note (nThreads)

`sign_recovery/batched_sign_recovery.py` hardcodes `nThreads=28` (sized for a
56-thread cloud box). On a 22 GB machine that spawns 28 TF processes and
swap-thrashes, stalling the Leaky sign recovery. `run_ablation.sh` temporarily
lowers it (env `SIGN_NTHREADS`, default 6) and **restores the file byte-for-byte
on exit** (trap). Resource constant only — changes no measured quantity. Set
`SIGN_NTHREADS=28` on a big box.

## Canonical config (per `run_one_model_enhanced.sh`)

SA+margin sign search, pair-lookahead 8, 3 sign-refine cycles (20-epoch mini
bursts), final fc5 LR refit, AdamW wd=1e-4 + cosine LR, early-stop patience 5 /
eval-every 10, train pool = X_test ∪ X_test2, eval = X_test3, query budget 20K.
refine-epochs: tiniest=300, tinier=500, tiny=500. reconstruct seed 42, scorecard
seed 0, margin-proxy subsample n_boundary=min(1500, |X_test3|).

## Gotchas hit

- `run_ablation.sh` creates `logs/`; if launching with a shell redirect to
  `logs/...` ensure the dir exists first (the redirect opens before the script).
- Launch as a single tracked background task, NOT nested `nohup ... &` inside
  another backgrounded shell (the grandchild gets killed when the launcher exits).
- Do not run overlapping victims concurrently on a memory-constrained box — the
  TF sign-recovery workers will OOM/thrash. Sequential (as run_ablation.sh does).
